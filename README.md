# Portfolio — Thalvindo

Personal portfolio, blog, project showcase, and guestbook.

> **AI-Generated Notice**: This project — codebase, Docker environment, and
> documentation — is >80% generated by AI (large language models). It serves as
> a demonstration of AI-assisted full-stack development.

## Architecture

```
        ┌─────────┐
        │  Nginx  │  :80 / :443 (TLS termination)
        └────┬────┘
             │ /
        ┌────▼─────────┐
        │  Next.js 14  │  :3000  — UI *and* data layer
        └────┬─────────┘
             │ Prisma
        ┌────▼─────────┐
        │ PostgreSQL16 │  :5432
        └──────────────┘
```

**There is no separate backend.** Server components query PostgreSQL directly
through Prisma, and every mutation (views, likes, guestbook signatures) is a
Next.js server action. That removes the HTTP hop, the duplicated types, and the
second deployable.

Three containers in `docker-compose.yml`: **db**, **frontend**, **nginx** —
the last two behind the `full` profile.

## Local Development

Postgres runs in Docker; the app runs on your machine with hot reload.

```bash
# 1. Environment
cp .env.example .env
cp frontend/.env.example frontend/.env

# 2. Database
docker compose up -d db

# 3. App
cd frontend
npm install
npm run db:deploy      # apply migrations
npm run db:seed        # sample posts + projects
npm run dev
```

Open **http://localhost:3000**.

To edit content, run `npm run db:studio` and open Prisma Studio at
http://localhost:5555. Post and project `content` fields hold HTML.

The `SiteSetting` table holds values you can change without a deploy. Editing a
row takes effect on the next request — no rebuild:

| Key | Drives |
| --- | --- |
| `contact_email` | The address on the homepage contact card; always shown |
| `contact_phone` | A `tel:` link |
| `linkedin_url` / `github_url` / `gitlab_url` / `youtube_url` | The icon links |
| `app_version` | The version in the footer |

**A blank contact row hides its link**, on both the homepage and the footer, so a
channel you haven't filled in never ships as a dead icon.

## Full Stack Locally

To run the production build behind Nginx, exactly as it is deployed:

```bash
docker compose --profile full up -d --build
```

Open **http://localhost:8090**. The frontend container applies migrations on
startup, so no manual migration step is needed.

Tear down with `docker compose --profile full down` (add `-v` to also drop the
database volume).

## Database

The schema lives in **one place**: `frontend/prisma/schema.prisma`, with
migrations in `frontend/prisma/migrations/`.

```bash
cd frontend
npm run db:migrate     # after editing schema.prisma — creates + applies a migration
npm run db:deploy      # apply existing migrations (CI, production, containers)
npm run db:seed        # upsert the sample content
npm run db:reset       # drop, re-migrate, re-seed
npm run db:studio      # GUI for authoring posts and projects
```

Tables: `posts`, `likes`, `views`, `projects`, `guestbook_entries`,
`site_settings`.
`likes` and `views` are unique per `(post_id, ip_address)` — one like and one
view per visitor.

## Environment Variables

Root `.env` configures docker compose. `frontend/.env` configures `npm run dev`.

| Variable | Description |
|---|---|
| `DATABASE_URL` | Connection string used by the app (`frontend/.env`) |
| `DATABASE_URL_DOCKER` | Same, but with host `db`, injected into the container |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_PORT` | Database service |
| `NGINX_CONF` | `./nginx/local.conf` (HTTP) or `./nginx/default.conf` (TLS) |
| `HTTP_PORT` / `HTTPS_PORT` | Host ports for Nginx |
| `NEXT_PUBLIC_APP_VERSION` | Fallback footer version, used only when the `app_version` setting row is missing |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Turnstile widget key; blank hides the widget |
| `TURNSTILE_SECRET_KEY` | Turnstile secret; blank skips verification (local dev) |

## Deployment

1. Provision a VPS (1GB RAM minimum, Ubuntu 22.04+) and install Docker:
   `curl -fsSL https://get.docker.com | sh`
2. Point DNS `A` records for `thalvindo.my.id` and `www.thalvindo.my.id` at it.
3. Clone the repo and write `.env` with a real `POSTGRES_PASSWORD`, a matching
   `DATABASE_URL_DOCKER`, Turnstile keys, and:
   ```
   NGINX_CONF=./nginx/default.conf
   HTTP_PORT=80
   HTTPS_PORT=443
   ```
4. Issue a certificate:
   ```bash
   docker run -it --rm -p 80:80 \
     -v /etc/letsencrypt:/etc/letsencrypt \
     certbot/certbot certonly --standalone \
     -d thalvindo.my.id -d www.thalvindo.my.id
   ```
5. `docker compose --profile full up -d --build`
6. Visit https://thalvindo.my.id

Generate secrets with:
```bash
openssl rand -base64 24 | tr -dc 'a-zA-Z0-9'
```
